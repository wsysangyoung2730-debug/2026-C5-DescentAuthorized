# 4~1층 구현 계획과 작업 이력

기준: `FLOORS_4_1_GAMEPLAY_DESIGN.md`, 2026-09-22.
시작점: `docs/floors-4-1-combat-plan` / `ab33c2e`.

## 범위

- 4~1층 각각 잔류체 A → 조사 → 잔류체 B → 중간문 → 관리자 → 보상/최종 기록 → 하강 승인 3단계.
- 후반 전투 턴당 3획, 마나 150 시험값. 7~5층 및 이전 층 규칙 유지.
- 신규 금서 4종·2획 봉인 주문 4종: 전체 주문 28종. 출전 6칸 중 금서 최대 2종.
- 잔류체 8종·관리자 4종의 HP, 예고, 예약, 모사, 반격, 봉인, 단계 전환.
- 기존 UI 스타일과 승인된 원본 적 이미지 적용. 여성 v2 이미지는 사용하지 않는다.
- 실제 Blender/GLB/USDZ 파일 제작·수정 제외. 후반부는 명시적인 2D 표현 경로를 사용하여 3D 준비를 기다리며 막히지 않게 한다.
- 출시 승인이나 밸런스 확정을 의미하지 않는다. 새 수치는 기획서의 시험값이다.

공통 기반 이후 독립 영역은 별도 작업 디렉터리에서 병렬 진행한다. 다른 작업의 파일을 덮어쓰지 않으며 공통 계약 변경은 먼저 공유한다. 마지막에 통합 브랜치로 병합하여 모든 변경이 한 브랜치에서 실행되게 한다. 각 커밋은 기능 단위로 작성하고 미완료 부분을 완료로 표시하지 않는다.

## 연결 계약

- `ExpansionProgress.residualIndex`: 0=A, 1=B. 5층 이상은 0만 사용.
- `residualInvestigation`, `recordReward`, `finalRecord` 단계 추가. 기존 단계 이름은 유지.
- 하강 성공 횟수는 4~1층 0...3, 기존 확장 0...2. 완료는 1층 최종 인계 이후에만 성립.
- 후반 보상 지점은 층 번호뿐 아니라 기록/관리자 구분으로 식별한다. 후보는 첫 진입 시 저장하고 학습 완료 후에만 주문을 지급한다.
- 이전 4층 입구 완료 저장은 4층 입구로 이어진다. A/B 전투 재개는 각 조우 준비 화면으로 복원한다.
- 각 브랜치의 신규 파일은 통합 시 Xcode 대상 등록을 확인한다.

## 점검 범위

전체 빌드·전체 테스트를 반복하지 않는다. 변경된 규칙의 좁은 검사와 저장 왕복·전이 확인을 우선하며, UI 확인을 위해 필요한 최종 빌드는 별도 기록한다. 실제 실행하지 않은 항목은 통과로 보고하지 않는다.

- 두 잔류체의 독립 승리/재도전, 보상 학습 전후 재개, 승인 2단계 이후 재개, 결말 재실행.
- 세 번째 금서 장착 거부, 학습 보관 유지, 기본 대응 주문 보호, 봉인 주문 등급 구분.
- 신규 2획 주문 완성/실패, HP 대가, 예약 취소·지연, 반격 억제, 방벽 소비·재생.
- 각 층의 조사·준비·조우·전투·패배·처치·보상·하강·결말 화면과 상단 HUD.
- 원본 이미지 누락, 3D 대기 교착, 작은 화면 넘침, 미리보기 저장과 실제 저장의 분리.
