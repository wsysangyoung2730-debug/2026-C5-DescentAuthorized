# Apple Pencil 및 손가락 입력 구현 계획

## 1. 목적

이 문서는 `하강 승인: 제0균열`에서 Apple Pencil과 손가락을 모두 정식 입력 수단으로 지원하기 위한 구현 기준을 정의한다. 플레이어는 설정 화면에서 입력 방식을 변경할 수 있어야 하며, 선택한 방식은 앱을 종료한 뒤에도 유지되어야 한다.

입력 장치의 차이가 게임 난이도나 최고 시전 등급을 제한해서는 안 된다. Apple Pencil은 더 정밀한 물리 입력을 제공하고, 손가락은 흔들림과 가림을 보정받지만 두 방식 모두 `완벽` 등급에 도달할 수 있다.

## 2. 구현 범위

### 포함

- 자동, Apple Pencil 전용, 손가락 전용 입력 모드
- 설정값 저장 및 앱 재실행 시 복원
- 입력 모드 변경의 즉시 반영
- UIKit 기반 실제 터치 및 Pencil 이벤트 수집
- 고빈도 coalesced touch 처리
- 팜 터치와 지원하지 않는 포인터 입력 차단
- 정규화 좌표 변환
- 비정상 좌표 제거, 중복점 축소와 손떨림 완화
- 1획 및 2획 주문 입력
- 현재 획 취소, 마지막 획 되돌리기와 전체 지우기
- SwiftUI에서 사용할 수 있는 캔버스 브리지
- 설정 화면의 입력 방식 선택 및 입력 확인 영역
- 기존 `GlyphEvaluator`, `CombatEngine`, `DemoGameSession` 연결 유지

### 제외

- Pencil 압력에 따른 공격력 변화
- Pencil 기울기에 따른 판정 차이
- 장치 종류에 따른 최고 등급 제한
- 멀티 터치로 여러 획을 동시에 그리는 기능
- Apple Pencil 호버를 게임 판정에 사용하는 기능
- Pencil 더블 탭에 주문 효과를 연결하는 기능

압력과 기울기는 향후 시각 효과에 사용할 수 있지만 핵심 판정에는 포함하지 않는다. 하드웨어 세대에 따른 유불리를 방지하기 위함이다.

## 3. 입력 모드

| 모드 | 손가락 | Apple Pencil | 동작 |
| --- | --- | --- | --- |
| 자동 | 허용 | 허용 | Pencil 입력이 감지되면 Pencil이 현재 획의 우선권을 가짐 |
| Apple Pencil | 차단 | 허용 | 손가락은 게임 획으로 수집하지 않음 |
| 손가락 | 허용 | 차단 | Pencil 접촉도 획으로 수집하지 않음 |

자동 모드는 기본값이다. Pencil이 없는 사용자도 설정을 변경하지 않고 플레이할 수 있고, Pencil 사용 중 발생하는 손바닥 접촉은 획으로 등록되지 않는다.

## 4. 자동 모드 충돌 규칙

1. 활성 입력이 없을 때 먼저 들어온 지원 입력으로 획을 시작한다.
2. 손가락 획 도중 Pencil 접촉이 시작되면 손가락 획을 취소하고 Pencil 획을 새로 시작한다.
3. Pencil 획 도중 발생한 손가락 접촉은 무시한다.
4. 하나의 획을 시작한 터치만 해당 획을 이동하거나 종료할 수 있다.
5. 입력 모드가 변경되면 진행 중인 획은 취소한다.
6. 시스템 취소 이벤트가 들어오면 미완성 획을 결과에 포함하지 않는다.
7. 최대 획 수를 채운 뒤 추가 접촉은 무시한다.

## 5. 좌표 처리 파이프라인

입력 좌표는 아래 순서로 처리한다.

1. UIKit에서 현재 캔버스 좌표 수집
2. 캔버스 크기가 유효한지 검사
3. X와 Y를 각각 `0...1` 범위로 정규화
4. NaN과 무한대 좌표 제거
5. 캔버스 경계를 벗어난 좌표를 경계값으로 제한
6. 장치별 최소 거리보다 가까운 연속 중복점 제거
7. 손가락 입력에 제한적인 3점 이동 평균 적용
8. 시작점과 종료점 보존
9. `DrawnStroke` 생성
10. `GlyphEvaluator`에 실제 입력 방식과 함께 제출

손가락 보정은 획의 의미를 바꾸지 않는 수준에서만 적용한다. 필수 노드를 자동으로 통과시키거나 경로를 가이드에 강제로 붙이는 보정은 사용하지 않는다.

## 6. 판정 보정

기존 판정기의 손가락 허용 반경은 정규화 좌표 기준으로 다시 정의한다. 좌표 범위가 `0...1`이므로 고정값 `1`을 더하는 방식은 사용할 수 없다.

| 항목 | Pencil | 손가락 |
| --- | --- | --- |
| 시작·필수·종료 노드 반경 | 기준값 | 기준값의 1.2배 |
| 경로 오차 반경 | 기준값 | 기준값의 1.15배 |
| 2획 교차 반경 | 기준값 | 기준값의 1.15배 |
| 최고 시전 등급 | 완벽 | 완벽 |
| 마나 계산 | 실제 경로 길이 | 보정 후 실제 경로 길이 |

정확한 배율은 실기기 플레이 테스트에서 조정한다. 초기 구현은 자동 테스트로 Pencil 기준 입력과 손가락 흔들림 입력이 각각 기대한 등급을 받는지 확인한다.

## 7. 설정 저장

설정은 게임 진행 저장과 분리한다. 새 게임을 시작하거나 체크포인트를 삭제해도 입력 방식은 유지되어야 한다.

저장 항목:

- 설정 데이터 버전
- 선택한 입력 모드
- 마지막 수정 시각은 필요하지 않으므로 저장하지 않음

저장소:

- 앱 실행: `UserDefaults`
- 자동 테스트: 메모리 저장소 및 격리된 `UserDefaults` suite

손상되거나 알 수 없는 설정값은 앱 실행을 막지 않고 자동 모드로 복구한다.

## 8. SwiftUI 설정 화면

설정 화면은 홈 화면의 톱니바퀴 버튼에서 연다.

- `입력 방식` 섹션에 자동, Apple Pencil, 손가락 세그먼트 제공
- 현재 선택값을 즉시 저장
- `입력 확인` 섹션에 실제 캔버스 제공
- 마지막 획 되돌리기와 전체 지우기 아이콘 제공
- 현재 입력을 Pencil 또는 손가락 아이콘으로 표시
- 지원하지 않는 입력은 획이나 오류로 기록하지 않음
- VoiceOver용 레이블과 선택 상태 제공

설정 화면의 입력 확인 캔버스는 판정 점수를 매기지 않는다. 선택한 입력 모드가 실제 장치에서 받아들여지는지만 확인한다.

## 10. 브랜치와 커밋 단위

- 설정 저장소
- 손가락 판정 반경 수정
- 단위 테스트

### `feat/#9-strokeProcessing`

- 좌표 정규화

- SwiftUI 브리지

## 11. 테스트 계획

### 도메인 테스트

- 기본 설정은 자동 모드
- 세 모드의 Pencil 및 손가락 허용 행렬
- 설정 저장 및 복원
- 손상된 설정의 기본값 복구

### 획 처리 테스트

- 화면 좌표의 정규화
- 경계 밖 좌표의 제한
- NaN과 무한대 제거
- 같은 위치의 과도한 샘플 제거
- 시작점과 종료점 보존
- 손가락 흔들림 감소
- 취소된 획 미등록
- 최대 획 수 제한

### 판정 테스트

- Pencil과 손가락 모두 완벽 등급 가능
- 동일한 작은 오차에서 손가락 허용치가 소폭 넓음
- 손가락이라고 필수 노드 누락을 통과하지 않음
- 입력 방식과 무관하게 마나 초과는 거절

### 통합 검사

- 설정 변경 즉시 캔버스 입력 정책 반영
- 앱 재실행을 가정한 설정 복원
- Swift Package 전체 테스트 통과
- iPad Simulator 앱 타깃 빌드 성공
- 기존 전투, 진행과 저장 테스트 회귀 없음

## 12. 완료 조건

- 설정 화면에서 세 입력 모드를 전환할 수 있다.
- 설정 선택이 앱 재실행 후 유지된다.
- 실제 캔버스에서 선택한 입력만 획으로 등록된다.
- 자동 모드에서 Pencil 사용 중 손바닥 접촉이 획으로 등록되지 않는다.
- 손가락과 Pencil 모두 동일한 주문과 최고 등급을 사용할 수 있다.
- 1획 및 2획 주문 데이터가 기존 판정 엔진에 정상 제출된다.
- 모든 자동 테스트와 iPad 앱 타깃 빌드가 통과한다.
