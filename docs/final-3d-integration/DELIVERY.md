# 7~1층 최종 3D 인계

18개 방과 18종 캐릭터를 최신 Blender 배치로 앱에 연결했다. 4~1층은 잔류체 A → 잔류체 B → 관리자 → 하강 흐름을 사용한다. 실제 구현과 검증은 로컬 누적 브랜치 `test/#166-final-3d-integration`에 있다. 브랜치·커밋 목록은 [COMMITS.md](COMMITS.md).

## 열어볼 파일

- 앱: 저장소 루트 `DescentAuthorized.xcodeproj`, scheme `DescentAuthorized`.
- 층별 편집본: 저장소의 형제 폴더 `../outputs/final-3d-release/Blender/Floor01_Final_Animated.blend`부터 `Floor07_Final_Animated.blend`까지 7개.
- 각 편집본에는 해당 층 2~3개 방, 카메라·앵커, 리그가 있는 캐릭터 미리보기, 가동 문짝, 패킹한 텍스처가 들어 있다. 외부 이미지 의존성 없음. 원본은 보존했다.
- 캐릭터 편집 라이브러리: 이 폴더의 `authoring/Floors75_FinalActors.blend`, `Floors43_FinalActors.blend`, `Floors21_FinalActors.blend`.
- 검토용 이미지: `../outputs/final-3d-release/Review`에 전체 캐릭터, 하강문 닫힘/열림, 후반층 보상 화면을 저장했다. 경로는 저장소 루트 기준이다.
- 최종 Blender 크기·해시·절대 경로: `validation/blender-delivery.json`.

## 적용 내용

- 승인된 스테이지, 잔류체 받침대, 소품과 카메라를 최신 원본에서 수출했다. 고정된 보상 두루마리는 복구하지 않고 실제 보상 후보를 슬롯에 동적으로 표시한다. 1층 최종 기록에는 선택 보상 3개를 생성하지 않는다.
- 3층 A는 동의 보관, B는 격리 집행이다. 제공 파일의 -1/-2 숫자와 게임 진행 순서가 달라 명시적으로 연결했다.
- 캐릭터마다 idle, idleVariant, appear, telegraph, attack, heavyAttack, special, hit, death 9개 클립을 등록했다. 장비 가중치와 지팡이 손 위치를 조정하고 기존 3층 관리자 스킨 가중치를 복구했다.
- 치명타 후 무력화 1.8초와 페이드 0.65초를 거쳐 캐릭터를 비활성화한다. 일시정지/복귀와 재도전의 opacity 복원이 연결되어 있다.
- 실제 7개 관리자 하강문을 좌우 가동 메시로 분리했다. 승인 직후 개방이 끝나기 전에는 다음 층으로 넘기지 않는다. 저장된 최종 승인 상태에서는 열린 상태로 복원한다.
- 후반층 3D 보상·하강 시점을 연결했다. 1~3층 전투 카메라에는 RealityKit 투영을 위한 별도 보정값이 있으며 1층 최종 전투 구도는 방 상단 밖이 보이지 않도록 좁혔다. Blender의 승인 카메라는 변경하지 않았다.
- 이전 9층 및 8층 캐릭터의 USD skeleton binding 누락도 복구하고 앱에서 관절·소멸을 확인했다.

## 최적화

- high/medium/low 텍스처 2048/1024/512. 이것은 텍스처 품질 단계이며 메시 LOD를 새로 만들었다는 뜻이 아니다.
- 동일 이미지 해시를 공유하도록 중복 파일 975개를 제거해 약 258.4MiB를 절약했다. 원본 이미지 재압축 없이 경로를 정리했다.
- 현재 방과 다음 방을 중심으로 준비한다. 환경 캐시 최대 2개, 다음 방 최대 1개, 보조 자산 최대 2개이며 메모리 경고 시 준비 작업을 취소하고 캐시를 정리한다.
- HDR 환경과 제한된 조명으로 런타임 비용을 조절했다. Blender와 RealityKit의 조명·그림자·프로시저럴 재질은 동일한 픽셀 결과가 아니며 최종 미술 검토는 앱 화면 기준으로 해야 한다.

## 실행한 검증

환경: Xcode, iOS 26.5의 iPad Pro 13 M5 시뮬레이터.

| 검사 | 결과 / 근거 |
|---|---|
| 최종 Debug 앱 빌드 | 성공 |
| 핵심 규칙 테스트 | 210개, 실패 0. 하강 승인 0/1/2/3 저장 복원 포함 |
| 18개 방 × 3품질 | 54개 자산의 카메라·앵커·텍스처 경로 검사 통과 |
| 신규 18종 + 기존 3종 × 3품질 | 63개 자산의 스킨·클립·텍스처 검사 통과 |
| 신규 캐릭터 18종 앱 실행 | 관절 변형, 공격, 소멸 opacity 0, 일시정지와 재시도 opacity 1 확인 |
| 장면 순회 | 같은 앱 프로세스에서 정방향·역방향·품질별·기존 층 포함 54회 준비 완료 |
| 상호작용 | 7개 하강문 개방, 2~4층 보상 모델 각 3개, 기존 8~9층 모션 확인 |
| 편집본 | Blender 7개 재열기, 18개 장면, 카메라·리그·패킹 텍스처 확인 |
| 원본 | Blender v067 및 제공 GLB 12개 SHA-256 불변 |

`validation/`에 위 결과를 JSON으로 저장했다. 입력 규칙/진행은 단위 검사, 3D 화면은 격리된 앱 진단 경로로 점검했다. 사람이 Apple Pencil로 7→1층을 처음부터 끝까지 플레이한 결과를 뜻하지 않는다.

54회 순회에서 scene-ready 중앙값 약 2.01초, 최대 약 6.42초였다. 앱 physical footprint는 약 147~373MiB였다. 첫 순회는 운영체제 디스크 캐시를 제거한 냉시작 시험이 아니다. 설치 CPU, 준비 완료, snapshot 완료는 별도 수치다. 시뮬레이터 Update 간격 약 16.7ms는 실기기 GPU 60fps 보증이 아니다.

## 남아 있는 실기기 확인 범위

실제 지원 iPad에서 GPU 프레임 시간·발열·메모리, Pencil 입력, 전체 플레이의 체감을 확인해야 한다. 품질별 이미지 비용은 추정치이며 GPU 사용량 실측이 아니다. 자연스러운 대기/공격/무력화 클립을 제작했으나 얼굴·손가락 모션 캡처와 천 시뮬레이션을 추가한 것은 아니다. 계획의 일부 코어 소등·잔류 증기 같은 개별 효과 대신 무력화와 공통 페이드로 종료를 통일했다.

## 재수출할 때

원본을 덮어쓰지 않고 복제본에서 작업한다. `export_final_rooms.py` → 기존 품질 변환 → `install_floor_assets.py` 순서 이후, 문 분리(`articulate_final_doors.py`), 텍스처 공유(`deduplicate_final_textures.py`), 화면 보정(`calibrate_final_presentation.py`)을 적용해야 한다. 설치 스크립트만 다시 실행하면 후처리한 문/재질이 덮어써질 수 있다.

캐릭터는 `build_final_actors.py`와 `install_actor_assets.py` 및 각 라이브러리를 기준으로 편집한다. 구조 검사는 `validate_final_assets.py`와 `validate_actor_assets.py`를 사용한다.

편집본 패키징은 `extract_editable_doors.py --output <문출력폴더>` 실행 후 Blender에서 `package_final_blender.py -- --raw <층별원본복제폴더> --doors <문출력폴더> --output <편집본출력폴더>`로 실행한다. `validate_blender_delivery.py`가 재열기를 검사한다. 캐릭터 미리보기의 `runtime_actor_preview` 표시는 배경 수출 시 이중 배치를 막기 위해 유지한다. 문짝의 Open 액션은 1프레임 닫힘/61프레임 열림으로 보관하고 자동 재생은 해제했다.
