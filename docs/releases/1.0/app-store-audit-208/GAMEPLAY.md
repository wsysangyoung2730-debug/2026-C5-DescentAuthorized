# 게임 진행·저장·접근성 출시 점검

- 점검일: 2026-10-02
- 최초 검토 기준: `57d03f0` (`fix/#207-acquisition-glyph-fidelity`)
- 범위: 실제 Release 진입 경로, 10~1층 완료 경로, 저장·복원·초기화, 생명주기, 입력과 접근성, 지원 기기에서의 안정성 위험
- 방법: Swift 소스와 기존 테스트 정의의 정적 검토. 이 문서 작성 작업에서는 앱 실행, 신규 테스트 실행, 실물 기기 측정, App Store Connect 검증을 하지 않았다.
- 아래 `파일:행`은 최초 검토 기준의 저장소 상대 경로다. #208에서 후속 수정이 들어가면 최종 상태·검증 결과는 상위 [README](README.md)와 해당 커밋을 함께 확인한다.

## 판단

게임 진행 소스에서 확정적인 출시 차단 결함을 발견하지는 않았다. 1층 이후 엔딩 경로, 저장 실패 처리, 장면 로딩 실패 시 복구 동작은 구현되어 있다. 그러나 이것이 심사 통과, 모든 기기에서의 정상 실행, 전 층 실제 플레이 검증을 뜻하지는 않는다.

출시 전에 우선 확인할 항목은 **구형 지원 iPad의 메모리·발열·긴 로딩**, **저장된 진행을 확인 없이 삭제하는 홈 버튼**, **접근성 지원 범위의 실제 검증과 정확한 표시**다. 개인정보·권리·용량·서명·스토어 입력값 등 이 문서 밖의 출시 조건은 상위 보고서에서 판단한다.

우선순위는 P2가 출시 전 수정 또는 검증 권장, P3가 품질 개선 또는 지원 범위 확인을 의미한다. 아래 항목을 Apple 심사 규정의 확정 위반으로 단정하지 않는다.

## 확인된 위험과 최소 조치

### G-01 · P2 · ‘처음부터’가 저장된 진행을 즉시 삭제

**코드에서 확인한 사실**

`DescentAuthorized/Features/Home/HomeView.swift:135`부터 저장된 게임이 있으면 계속하기와 처음부터 버튼이 나타난다. `:145–154`의 처음부터 버튼은 별도의 확인 없이 `gameSession.startNewGame()`을 호출한다. 최종적으로 `DescentAuthorized/Core/Game/GameSessionCoordinator.swift:41–44`에서 저장 파일을 삭제하고 새 세션으로 교체한다.

**사용자 영향**

계속하기 옆의 버튼을 잘못 누르면 여러 층의 진행이 즉시 사라진다. 일시정지 메뉴의 전투 재시작과 튜토리얼 기록 초기화에는 확인창이 있지만, 더 큰 범위의 홈 초기화에는 없다.

**최소 권장 조치**

저장된 진행이 있는 경우에만 확인창을 표시한다. 삭제 대상이 게임 진행·해금·보상이라는 점을 실제 초기화 범위에 맞게 알리고, 취소 시 저장 파일과 세션이 그대로인지 확인한다. 새 설치의 첫 시작에는 확인창이 필요하지 않다. 이 문제는 데이터 손실 위험이며, 심사 거절을 확정하는 근거는 아니다.

### G-02 · P2 · 최소 지원 iPad에서 성능·안정성 미검증

**코드에서 확인한 사실**

`DescentAuthorized.xcodeproj/project.pbxproj:779`는 iOS 18.0, `:787`은 iPad 기기군을 대상으로 한다. 최신 시뮬레이터 한 종류로 동작했다는 사실은 이 지원 범위 전체의 RAM·GPU·열 조건을 보증하지 않는다. 여러 장면과 다음 공간을 준비하는 구조이므로 연속 층 이동과 전투 중 최대 메모리도 함께 측정해야 한다.

**아직 확인하지 못한 것**

지원 기기 중 성능·메모리가 낮은 실물 iPad에서의 첫 로딩 시간, 메모리 압박 종료 여부, 20분 이상 플레이의 발열·프레임 저하, 백그라운드 복귀 후 복원, 남은 저장 공간이 적을 때의 실패 처리.

**최소 권장 조치**

최소 지원 사양의 실물 iPad와 현재 주력 실물 iPad에서 Release/TestFlight 후보를 검증한다. 장면별 로딩 시간, 최대 메모리, 프레임 정체, 종료 로그를 기록하고 앱 내부 ‘낮음’ 그래픽 설정도 포함한다. 통과하지 않은 기기를 지원한다고 유지할 경우 성능 개선 또는 지원 범위 재검토가 필요하다. 본 점검은 지원 기기 축소를 임의로 적용하지 않는다.

### G-03 · P3 · 시스템 ‘동작 줄이기’와 3D 연출 연결이 일관되지 않음

**코드에서 확인한 사실**

`DescentAuthorized/Features/Progression/DemoFlowView.swift:5`는 시스템 `accessibilityReduceMotion`을 읽지만, `:42`의 3D 장면에는 앱 내부 설정인 `appSettings.reducedMotion`만 전달한다. `DescentAuthorized/Features/Battle/BattleView.swift:351–355`의 전투·진행 연출 설정도 앱 내부 값만 사용한다. 반면 일부 학습·문양·전환 UI는 시스템 설정과 앱 설정을 OR 처리한다.

**사용자 영향과 조치**

기기 설정에서 동작 줄이기를 켰어도 일부 3D 움직임이 계속될 수 있다. 앱 설정 또는 시스템 설정 중 하나라도 켜지면 관련 카메라·전투·배경 효과에 적용하도록 공통 정책을 두는 것이 적절하다. 앱의 ‘번쩍임 줄이기’는 별도 기능이므로 회전·이동 감소와 동일하게 취급하지 않는다. 시스템 설정을 앱 실행 중 변경하는 경우까지 실제 화면에서 확인해야 한다.

### G-04 · P3 · 문양 입력판의 VoiceOver 포커스와 전체 플레이 가능 여부 미확인

**코드에서 확인한 사실**

`DescentAuthorized/Features/Battle/Input/RuneDrawingCanvasView.swift:275–282`는 접근성 label과 `.allowsDirectInteraction`을 설정하지만 `isAccessibilityElement = true`는 설정하지 않는다. 일반 `UIView`의 기본 동작상 입력판이 독립적인 접근성 요소로 노출되지 않을 수 있다. 주변 SwiftUI 접근성 구성까지 포함한 실제 노출 결과는 실행으로 확인해야 한다.

**최소 권장 조치와 제한**

입력판 포커스·직접 조작 진입·획 수 읽기·초기화·시전 순서를 VoiceOver로 검증한다. 포커스 노출을 보완해도 시각적 핵심점을 따라 문양을 그리는 게임 전체가 비시각적으로 플레이 가능하다고 보증할 수는 없다. 검증 전에는 스토어 접근성 정보에서 VoiceOver로 전체 플레이 가능하다고 표시하지 않는다. 필수 튜토리얼과 긴 안내의 큰 글씨·대비·읽기 순서도 별도로 확인한다.

### G-05 · P3 · 마우스·트랙패드 필기는 지원하지 않음

`DescentAuthorized/Features/Battle/Input/RuneDrawingCanvasView.swift:315–324`는 Pencil과 직접 터치만 입력으로 처리하고 `.indirect` 및 `.indirectPointer`를 거부한다. 손가락 또는 Pencil로 플레이하는 게임이라는 설명과는 일치한다. 다만 포인터·키보드·보조 입력만으로 전체 게임을 플레이할 수 있다고 주장하려면 추가 구현과 검증이 필요하다. 현재 확인 결과만으로 이를 필수 출시 결함으로 취급하지 않는다.

### G-06 · P3 · 이어하기가 전투 중간 상태 저장은 아님

`DescentAuthorized/Core/Progression/GameProgressionController.swift:44–57`는 재실행 시 진행 중 전투를 준비 상태로 복원하며 전투 중이었다면 체력을 다시 채운다. `DescentAuthorized/Core/Progression/ExpansionProgress.swift:61–67`도 전투·조우를 준비 단계로 변환한다.

이는 의도된 체크포인트 복원 정책으로 보이며 결함으로 단정하지 않는다. 도움말·스토어 설명은 ‘진행 상황 또는 체크포인트 이어하기’로 설명하고, 종료 직전의 턴·체력·예약 공격 상태까지 보존한다고 약속하지 않아야 한다. 전투 승리·보상 학습·하강 승인 후에 앱을 종료했을 때 이미 완료한 결과가 중복 지급되거나 누락되지 않는지는 실기 검증 대상이다.

## 검토 한계

- 기존 저장·카탈로그·진행·서사 테스트 정의를 읽었지만 이 하위 점검에서는 테스트를 다시 실행하지 않았다. 실행 결과와 빌드 로그는 상위 보고서에서 확인한다.
- 실제 Release 바이너리의 진단 코드 배제, 앱 번들 자원 완전성, 코드 서명, 메모리 사용량은 소스 검사와 별개로 확인해야 한다.
- 전체 게임의 자연스러운 공격 모션·문양 일치·로딩 품질에 관한 이전 시뮬레이터 작업과, App Store 후보의 실제 기기 검증은 별도의 증거다.
- 한국어 외 언어 지원, App Store에 선택할 접근성 지원값, 지원 국가·심사 계정·연령 등급은 이 코드 검토만으로 확정할 수 없다.
