# #170 4층 진입 경로 조사 및 전환 복구

- 브랜치: `fix/#170-floor4-entry`
- 시작점: `fix/#169-descent-props-failure`, `f376e3a`
- 원격 fetch 후 최신 로컬 #169의 수정까지 포함해 분기했다.
- 사용자 증상: 4층 내부 진행이 아니라 4층 진입 자체가 불가능하다.

## 소스 및 에셋 조사

- 5층 하강은 승인 2단계 완료 → 문 열림 대기 → `.advanceExpansion` 순서다.
- 진행 컨트롤러는 5층에서 4층 entrance로 전환하며 승인 수와 잔류체 인덱스를 0으로 초기화한다. `floor5Complete` 체크포인트도 4층 입구에 연결되어 있다.
- 4층 첫 방의 카메라, 적 배치 및 입력판 앵커와 캐릭터 기준 객체는 USD에 존재한다. 4층을 막는 의도적인 진행 제한은 찾지 못했다.
- 확인된 복구 결함: 문 열림 대기가 false를 반환하거나 최종 진행 명령이 실패하면 입력 화면은 이미 숨겨져 있고 `isCompletingDescent`는 true로 남는다. 기존 승인 화면의 재시도 버튼에도 접근할 수 없다.
- 4층 첫 방은 보상 장치가 없어 보상 URL 배열이 비어 있다. 기존 로더는 이 경우도 빈 `MergeMany`/`collect`와 방 로드를 `zip`했다. 무의존성 경로를 명시적으로 처리하도록 변경했다. 동일 구조는 다른 층 잔류체 방에도 있으므로 이것만으로 4층 증상의 직접 원인이라고 단정하지 않는다.

## 변경

- 보상 의존성이 없으면 빈 리소스 사전을 한 번 즉시 전달하여 방 설치 경로에 연결한다.
- 문 열림 중단 또는 진행 명령 실패 시 원인을 표시하고 `하강 다시 진행` 버튼을 제공한다.
- 재시도는 완료한 승인을 유지하며 문 열림 상태만 재설정한다. 실제 진행 저장은 기존 명령으로 처리한다.
- 화면 이탈에 의한 작업 취소는 이전처럼 취소로 처리하고, 중복 하강은 기존 완료 중 플래그로 차단한다.

## 남은 확인

사용자 요청에 따라 빌드·자동 테스트·시뮬레이터 실행은 하지 않았다. 실제 정지 화면이 문 열림 이후인지, 4층 로딩/오류 화면인지는 추가 답변을 기다리고 있다. 따라서 위 변경은 확인된 복구 결함 수정과 로딩 경로 보강이며, 보고된 진입 불가 증상의 원인 확정 또는 재현 해결 완료를 의미하지 않는다.

사용자 확인 지점: 5층 2차 승인 후 4층 조사 화면 진입, 저장된 승인 완료 상태에서 이어하기, 4층 로딩 오류가 남을 경우 표시 문구. 원본 Blender/GLB와 모션은 변경하지 않았다.

## 추가 제보: 4층 조사 카드 클릭 불가

사용자가 제공한 후속 화면에는 4층 배경, `기억 손실 위험 고지` 카드와 조사 기록 패널이 이미 표시되어 있다. 따라서 이 화면의 막힘은 4층 로딩 실패가 아니라 기록 열람 입력 문제로 좁혀진다.

하층 공통 `actionButton`은 진행 버튼 배경에 `scaledToFill` 이미지를 넣고 `clipped()`만 적용했다. 시각적 자르기와 터치 영역은 별개여서 버튼 밖으로 확장된 이미지가 위쪽 기록 카드와 겹칠 수 있다. 특히 기록을 읽기 전에는 이 버튼이 비활성화되어 있어, 가로챈 터치가 아무 반응 없이 끝날 수 있다.

- 진행 버튼 장식 이미지의 터치 판정을 끄고, 버튼 레이블의 `contentShape`을 실제 사각형으로 제한했다.
- 조사 카드에도 사각형 터치 영역을 지정해 텍스트 사이와 여백을 눌러도 열람할 수 있도록 했다.
- 카드 및 기록/대화 패널의 장식 테두리는 터치를 받지 않도록 했다. 기록 스크롤과 대화 진행 버튼에도 같은 처리를 적용했다.
- 4~1층이 사용하는 공통 화면에 적용했다. 기록을 읽어야 준비 버튼이 활성화되는 진행 조건은 유지했다.

이번 수정도 빌드·자동 테스트·시뮬레이터 실행 없이 커밋했다. 실제 터치 증상 해결 여부는 사용자 실행 확인이 필요하다.
