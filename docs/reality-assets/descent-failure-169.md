# #169 5층 하강 장치 고정 및 5~1층 실패 제한

브랜치: `fix/#169-descent-props-failure`
시작 커밋: `d294666` (#168의 모션·대화 수정 포함)

## 원인과 변경

- 5층 관리자 방의 하강 비석/발판은 문짝과 별도 오브젝트이며, 정적 USD에 별도 이동 애니메이션도 없다. 런타임에서 입력 시 발판을 1.025배, 승인 시 발판을 1.07배/비석을 1.025배 확대하고 실패 시 발판을 흔들었다.
- 5층의 해당 효과를 제거했다. 매 상태 변경 때 원래 배치를 복원하며 문짝 개방과 카메라 반응은 유지한다.
- 8층은 하강 입력 실패 기회가 2회이고, 두 번째 실패 시 카메라 붕괴 연출과 실패 화면을 표시한다. 재시도는 통과한 단계에서 이어진다.
- 5층은 기존 실패 제한이 없었다. 이를 2회로 변경하고 기존 8층 실패 화면·카메라·재시도 절차를 사용한다.
- 4~1층의 3개 승인 문양 입력에도 동일한 2회 실패 제한을 추가했다. 첫 실패는 거절 반응 후 현재 문양을 다시 입력한다. 두 번째 실패는 입력을 차단하고 8층과 같은 게임오버 화면을 표시한다.
- 하층 재시도는 카메라와 현재 입력을 초기화하고 기회를 2회로 회복한다. 이미 저장된 승인 단계는 유지한다. 성공한 중간 단계가 실패 횟수를 초기화하지 않는다.
- 승인 단계 유지 여부를 실패 횟수 제한과 분리했다. 5층의 '현재 단계 초기화'가 저장된 앞선 승인과 어긋나지 않도록 했다.
- 실패 연출 중 중복 제출·초기화를 막고, 화면 이탈 시 진행 중인 실패/재시도 작업과 카메라 효과를 정리한다.
- 6·7층의 기존 무제한 실패 설정은 이번 요청 범위 밖이므로 유지한다.

## 동작 범위

8층과 마찬가지로 이 게임오버는 봉인 검수 재시도 화면이며, 전체 게임 저장을 지우거나 층을 다시 시작하지 않는다. 실패 횟수는 현재 검수 화면에 머무는 동안 유지되고, 승인 기록은 기존 저장 데이터를 사용한다.

## 인계

코드와 USD 구조를 읽어 원인을 확인했다. 사용자 요청에 따라 빌드, 자동 테스트, 시뮬레이터 실행은 하지 않았다. 수동 확인 대상은 5층 하강 장치 고정, 5~1층 두 번 실패 후 입력 차단/게임오버, 재시도 후 현재 단계 유지와 기회 회복이다.
