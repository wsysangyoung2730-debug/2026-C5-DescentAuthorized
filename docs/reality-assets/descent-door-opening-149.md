# #149 연속 문 개방 — 1차 구현

브랜치: `fix/#149-descent-door-opening` (기준: #148 최적화)

## 적용 범위

현재 분리된 문짝·문틀·포털 표면이 연결된 10~8층에 적용했다. 별도 열린 문 모델은 표시하지 않으며, 기존 닫힌 문의 문틀과 상단 문양을 유지한다.

- 2.2초 개방 구간: 최초 12%는 해제 대기, 이후 smoothstep 곡선으로 좌우 문짝 이동.
- 이동 거리는 포털 폭을 기준으로 산정하며 기존 최소 이동 거리를 보장한다.
- 문짝은 크기를 바꾸지 않고 평행 이동한다. 포털은 기존 닫힘 상태의 세로 압축을 풀고 이동 진행도에 맞춰 투명도를 올린다.
- 매 프레임 장면 검색·경계 계산을 하지 않고 부착 시 확보한 문짝 참조와 변환을 사용한다.
- 승인 상태가 반복 전달돼도 개방을 처음부터 재생하지 않는다. 열린 상태는 동일 모델의 최종 위치를 유지한다.
- 동작 줄이기는 동일한 최종 위치를 즉시 적용한다. 장면 초기화·닫힘 상태 복귀 시 진행 작업을 취소하고 원래 위치로 복구한다.
- 하강 흐름은 고정 1.867초 타이머 대신 개방 작업 완료를 기다린다. 초기화/취소 세대가 달라지면 하강을 진행하지 않는다.
- 아직 분리된 문이 없는 장면은 기존 대기 시간을 유지한다.

## 남은 결정 및 작업

전체 층 통일 완료가 아니다. 7층은 부품 재분류가 필요하고 6층은 단일 메시 문이다. 5층은 기존 기획상 문이 없는 실제 하강 통로와 동선 밖 장식용 문이 분리돼 있다. 7~5층에 공통 분리 문을 배치할지, 각 층 외형을 유지하며 자산을 재가공할지는 사용자 결정 후 진행한다. 4~1층의 2D 진행 화면에는 이번 3D 변경을 적용하지 않았다.

## 검증

- 기존 USD에서 10~8층 좌우 문짝과 포털 제어 노드 확인. 잠금 코어는 비어 있어 기존 회전/축소 연출을 제거했다.
- iOS Simulator arm64 Debug 빌드로 컴파일 확인.
- 실기기 및 시뮬레이터에서의 개방 영상·벽 관통·재질·가림 검증은 아직 수행하지 않았다. 특히 좌우 문짝이 프레임 바깥으로 이동할 때 주변 벽에 자연스럽게 가려지는지 확인이 필요하다.

## 수동 검증 항목

1. 10·9·8층 각각 마지막 문양 승인 후 문틀이나 상단 문양이 순간 바뀌지 않는지 확인.
2. 좌우 문짝이 감속하여 멈추고 포털이 틈 뒤에서 드러나는지 확인.
3. 개방 중 동작 줄이기 설정 변경, 화면 이탈, 장면 재로딩, 재진입에서 문 위치와 하강 상태 확인.
4. 각 화질에서 문짝의 이동 방향·통로 폭·주변 벽 관통 여부 확인. 최종 열린 상태 2.4초 후 하강 확인.
