# 9층 Apple 자산 로딩 최적화 (#106)

9층 진입 시 방과 숨겨진 보스를 모두 기다리던 경로를 분리했다. 조사 화면은 방이 준비되면 사용 가능하며, 보스 공개는 배우 준비가 끝난 뒤 진행한다. 10층 하강문에서 다음 방을 비동기로 미리 읽는다. 미리 읽기 캐시는 한 방만 보관하고, 품질 변경 및 메모리 경고 시 기존 대기 자산을 해제한다. 실제 장면에는 메시·텍스처를 공유하는 복제본을 전달한다. 실패 시 기존 오류/재시도 화면을 유지한다.

## 자산 통합

- 원본 기준: c20e956의 ArchiveRedesign 및 RecordAdministrator.
- 불투명 기본색 재질 중 상수 값이 같고 UV가 0–1 범위에 있는 작은 텍스처만 아틀라스로 통합한다.
- 1024px 이상의 원본 질감은 개별 보존한다. 서버랙 등의 작은 표시가 사라지지 않도록 과도한 축소를 피했다.
- 가장자리 8px 확장, 빈 여백 제거, UV 재배치. 카메라·오브젝트 변환·두루마리 모션은 유지한다.
- 최고/중간/낮음은 최대 2048/1024/512px. 보스도 이제 품질 설정을 따른다.
- 참조하지 않는 기존 텍스처는 두 자산 폴더에서 제거했다.

|항목|기존|변경|
|---|---:|---:|
|방 재질 / 텍스처|221 / 224|43 / 49|
|보스 재질 / 텍스처|167 / 168|30 / 31|
|합계 재질 / 텍스처|388 / 392|73 / 80|
|중간 품질 텍스처 메모리 추정|약 642 MiB|약 415 MiB|
|낮은 품질 텍스처 메모리 추정|약 594 MiB|약 104 MiB|
|최고 품질 텍스처 메모리 추정|약 834 MiB|약 790 MiB|

메모리 값은 이미지 크기에 RGBA8과 밉맵 4/3을 적용한 비교용 추정치다. 작은 상수 EXR, 반사 환경, 기하 정보, 디코딩 임시 버퍼와 엔진 내부 포맷은 제외한다. 실제 앱 메모리 측정값이 아니다. 최고 품질은 여전히 무거우며, 기본 중간 품질에서 절감 폭이 더 크다.

## 반사와 밝기

Blender 9층 장면에서 512×256 HDR 반사 환경을 캡처했다. RealityKit의 환경광 배율은 +2.5, 기존 직접 조명은 -0.5 EV에 해당하는 배율을 사용한다. 광원 개수를 늘리지는 않았다. 조명 위치 판별은 램프 메시의 실제 경계 중심을 사용한다. 방을 나가면 적용한 환경광을 초기화한다.

이는 반사 환경과 밝기 보정이며 전체 간접광 라이트맵 베이크 또는 Blender AgX 색 변환의 복제는 아니다. RealityKit과 Cycles의 그림자·톤 매핑 차이는 남는다.

## 재생성

원본 커밋의 자산을 별도 디렉터리에 추출한 뒤 Blender의 pxr 지원 Python으로 실행한다. 이미 통합된 현재 자산을 원본으로 재입력하지 않는다. 출력 디렉터리는 새 경로여야 한다.

```sh
USD_PYTHON docs/reality-assets/atlas_floor9.py --source-root ORIGINAL_REPO_SNAPSHOT --output NEW_OUTPUT_DIRECTORY --image-python PYTHON_WITH_PILLOW
Blender --background ORIGINAL_BLEND --python docs/reality-assets/bake_floor9_environment.py -- --output OUTPUT_HDR
```

두 자산 하위 폴더의 생성 결과를 게임 리소스에 반영한다. 반사 캡처 스크립트는 DA_F09_Archive_Redesign 장면을 요구하며 원본 blend를 저장하지 않는다.

## 검증

- iOS Simulator Debug 빌드 성공.
- 여섯 USD 품질 자산의 상대 참조 및 텍스처 존재 확인.
- 기존 9층 모션 검증: 카메라 3개, 13×66 로컬 변환, 자동 재생 없음, 오른쪽 뚜껑 35도 통과.
- 중간 품질 진입 미리보기에서 방 준비 후 보스가 별도로 준비되는 실행 순서와 재질 화면 확인.
- 진단 인수: --floor9-preview --boss --graphics-medium --entrance (Debug 전용, 저장 진행 없음).
- SceneLoading 로그의 room.begin / room.decoded / room.ready / actor.begin / actor.ready로 실기기 지연을 구분할 수 있다.

실제 iPhone/iPad에서의 시간 및 메모리 개선율은 아직 측정하지 않았다. 시뮬레이터 측정은 실기기 성능 보장이 아니다.
