# 8·10층 재질과 카메라 복구 (#110)

브랜치: `fix/#110-floor10-materials-camera`

## 수정 내용

- 10층 조사 완료 버튼을 `훈련 표적 앞으로 이동하기`로 변경하고 이동 후 훈련 표적 정면 카메라를 사용한다. 기존 학습·진행 순서는 유지한다.
- Blender 절차적 재질을 공유 PBR 텍스처로 변환한다. 벽의 높이별 오염은 수직 평면에서 베이크하여 바닥 높이의 어두운 색이 벽 전체에 적용되지 않게 한다.
- 가져온 소품의 indexed face-varying UV를 펼쳐 삼각형 단위 텍스처 왜곡을 방지한다.
- 8층 파티션과 크레이트를 원본에서 각각 약 12만 삼각형으로 다시 줄여 근접 형태를 복원한다. 보스방 총 삼각형은 607,066개로, 원본 약 775만 개보다 약 92% 적다.
- 각 방의 작은 HDR 반사환경과 제한된 개수의 조명을 사용한다. 가져온 조명과 실행 중 조명이 중복되지 않도록 처리한다.
- 8층 보상 카메라를 조정하고 시야를 막던 기물을 옮긴다. 9층과 같은 애니메이션 재생 경로를 사용하며, 13개 트랙의 상승이 끝난 뒤 선택 화면을 표시한다.

## 확인 결과

- iPad Pro 13-inch (M5), iOS 26.5 시뮬레이터 Debug 빌드 성공.
- 10층 표적 정면 카메라, 8층 잔류체 방 재질, 8층 보스방과 세 두루마리 상승을 자산 미리보기에서 확인.
- 저·중·고 품질의 9개 자산에서 텍스처 경로, UV 개수, 카메라 광학 단위 확인.
- 보상 13개 트랙의 66프레임 값, 초기 변환 일치, 상승 높이 확인.
- 전체 테스트 반복은 생략. 실제 플레이의 조사→학습 연속 흐름과 물리 기기의 FPS·발열·로딩 시간은 별도 확인이 필요하다.

## 재검증

`validate_room_repairs.py`에 `DescentAuthorized/Resources/Reality/Scenes` 경로를 인자로 전달한다. `pxr`가 제공되는 Python 환경이 필요하다.

Debug 실행 인자 `--floor9-preview`와 `--floor10`, `--floor8-residue`, `--floor8-boss` 중 하나를 사용한다. `--main`은 입장 카메라, `--boss`는 전투 카메라를 선택한다. 인자가 없으면 보상 카메라를 사용한다. 미리보기는 실제 플레이 저장을 진행시키지 않는다.

## 범위와 제한

원본 `.blend`는 변경하지 않았다. 변환·베이크·세부 형태 복구 스크립트는 같은 디렉터리에 보관한다. 공유 텍스처는 8m 투영 기준이며 Blender의 모든 절차적 셰이더와 렌더링 효과를 픽셀 단위로 재현하는 방식은 아니다. 반사환경과 직접 조명으로 실행 화면을 보정하되 실기기 성능 수치는 이번 검증에 포함하지 않았다.
