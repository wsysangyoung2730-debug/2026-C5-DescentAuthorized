## 변경

제작한 패널, 상단 문양, 기본/선택 카드, 확인 버튼, 체크, 정보 배지 PNG 7종을 등록했다. 원본 PNG는 보존하고 표시 시 투명 여백만 제거하며 패널과 카드의 빈 중앙 부분을 늘린다.

공통 `BattleSealChoiceView`는 최대 너비 560pt의 창에 후보를 표시한다. 기존 88% 검정 막은 52%로 낮췄다. 주문 선택은 화면 내부 상태로 유지하고, 금색 테두리·체크·선택 설명을 확인한 뒤 ‘이 주문 봉인’을 눌러 기존 `chooseCardSeal` 명령을 전송한다. 선택 전에는 확정 버튼이 비활성화된다. 실제 봉인은 종전대로 적 행동 시 발생한다.

주문명·문양·유형·효과·필요 획수와 봉인 기간은 실제 전투 데이터로 표시한다. 화면 높이가 부족하면 세로 스크롤, 후보가 많으면 가로 스크롤을 사용한다. 후보 변경 시 유효하지 않은 선택을 지우며 전투/턴이 달라지면 선택 상태를 새로 만든다.

현재 선택형 봉인은 3층 동의 보관 잔류체(1턴), 자발 격리 관리자(3턴)가 사용한다. 층 번호와 무관하게 `needsSealChoice` 조건에 연결되어 있다. 5층 및 1층 관리자의 자동 봉인은 기존 규칙을 유지한다.

## 최소 검증

- iPad 시뮬레이터 Debug 빌드 성공.
- 기존 `LowerFloorTests.testSealChoiceBlocksInputAndProtectsCoreCards` 1건 통과: 보호 카드 제외, 선택 전 행동 차단, 확정한 주문 봉인.
- 3층 관리자 화면에서 미선택 상태와 선택 상태를 확인했다. 최종 선택 상태는 DEBUG 전용 `--preview-seal-choice riftSeverance`로 재현했다.
- 최종 화면에서 3턴 배지, 금색 선택 테두리/체크, 선택 설명, 활성화된 확인 버튼과 작아진 패널을 확인했다.
- `git diff --check` 통과.

사용자 요청에 따라 검증을 확대하지 않았다. 실제 터치부터 전투 복귀까지의 UI 동작, 잔류체 개별 화면, 실기기 및 큰 글자 크기 검증은 수행하지 않았다. Simulator 창을 컴퓨터 조작 도구가 찾지 못해 터치 검증을 완료하지 못했다.
