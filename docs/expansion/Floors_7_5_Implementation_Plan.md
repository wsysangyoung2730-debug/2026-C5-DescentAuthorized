# 7~5층 플레이 프로토타입 구현 계획

상태: 구현 전 계획. 이번 작업에서는 브랜치를 생성하거나 게임 코드를 수정하지 않았다.

대상 저장소는 현재 기획·에셋·기존 UI가 있는 `2026-C5-ipadOS`로 잡는다. 로컬 현재 브랜치는 develop이며, 실제 착수 시 원격 상태와 분기 기준 커밋을 다시 확인한다. 현재 미추적 파일 docs/RUNE_TOWER_PRD.md는 기존 사용자 작업으로 보존한다.

## 1. 목표

새 3D 모델과 배경 없이도 기존 9·8층과 같은 UI 체계에서 9·8층의 실제 보상 선택, 가방 구성, 7~5층의 6개 전투, 6층 신규 규칙 학습, 보상 및 2단계 하강 승인을 끝까지 플레이한다.

겉모습이 임시인 부분과 동작까지 가짜인 부분을 혼동하지 않는다. 배경과 적 이미지는 임시여도 주문 판정·피해·상태 효과·장착 조건·보상·진행·재도전은 실제로 작동해야 한다.

## 2. 확인한 기존 구조와 적용 원칙

- DemoFlowView는 RealityStageView 위에 HUD와 각 진행 화면을 올린다. isPresentationReady가 3D 장면과 카메라 준비를 확인하므로 임시 층을 단순 추가하면 UI 진입이 막힐 수 있다.
- BattleView에는 기존 카드 프레임·주문 상세 패널·자원·턴 종료·전투 기록이 있다. 다만 주문 ID 5개와 카테고리 3개를 직접 분기하는 부분은 확장해야 한다.
- 주문서 등급 4종과 등급 배지는 이미 있다. 등급 UI를 새로 만들기보다 재사용한다.
- RewardSelectionView에는 3개 선택·상세·확정 UI가 있지만 9층은 모두 같은 주문, 8층은 등록 주문 없음이다. 실제 후보·문양·효과 공개·시험 각인으로 동작을 교체한다.
- 보상 및 하강 화면이 RealitySceneController의 연출을 호출한다. 새 층은 실제 3D 연출 완료를 기다리지 않고도 같은 UI 흐름이 끝나는 표현 경로가 필요하다.
- DescentSealProcedureView는 현재 9·8층에 이미 2단계 설정이 있다. 레이아웃과 입력 구조를 재사용할 수 있다.
- 기존 하강 설정에는 maximumAttempts=2와 붕괴·재시도 흐름이 있다. 최신 신규 층 기획의 무제한 재제출·1단계 성공 유지와 다르므로 새 층의 정책을 설정으로 분리한다. 기존 층 동작을 무심코 덮어쓰지 않는다.
- 현재 저장 형식은 버전 2이며 보유 주문은 있지만 장착 주문 목록·기본 대응 지정은 없다. 하위 호환 처리가 필요하다.
- Package.swift의 코어 테스트와 기존 통합·패턴·문양·진행 테스트를 활용할 수 있다. UI 확인은 별도 앱 빌드와 실행이 필요하다.

### B. 새로 만들되 기존 UI 규칙에 맞출 화면

| 영역 | 내용 |
|---|---|
| 가방·출전 준비 | 보유 주문에서 최대 6종 장착, 봉인 해제 필수, 공격·방어 각 1종 이상 |
| 기본 대응 지정 | 선택한 공격·방어를 카드 봉인에서 보호하도록 지정 |
| 자기/적 대상 선택 | 정화·예약 말소 등에서 효과 대상 선택과 사용 가능 여부 표시 |
| 상태 효과 표시 | 버프·디버프 이름, 대상, 남은 기간·소모 조건, 상세 설명 |
| 예약 피해 목록 | 도착 턴, 피해량, 지연 가능 여부와 취소·지연 결과 |
| 모사 기록 | 기록한 주문과 재사용 시 발생할 결과 표시 |
| 카드 봉인 | 사용할 수 없는 카드, 해제 시점, 보호 주문 구분 |
| 신규 층 진입 | 최소 안내와 들어가기 버튼으로 전투 준비 연결 |
| 확장 종료 | 5층 보상·하강 완료와 시험 각인 연결 |

기존 서체·색·패널 프레임·카드·버튼·여백·누름 상태를 사용한다. 화면을 단순 개발 메뉴나 텍스트 버튼 목록으로 대체하지 않는다. 디버프용 새 카드 표시는 기존 카드 형식과 임시 식별 아이콘/색으로 구현하되 전용 최종 아트는 추후 교체 가능하게 둔다.

### C. 이번에는 임시 표현

| 영역 | 임시안 | 나중에 교체할 대상 |
|---|---|---|
| 7~5층 배경 | 층별 톤을 적용한 단순 배경 또는 정적 무대 | 최종 공간·3D 배경 |
| 적 | 선택한 잔류체·보스 이미지를 정적 배치 | 리깅된 3D 적 모델 |
| 적 동작 | 간단한 강조·흔들림·명도 변화 | 공격·피격·단계 전환 애니메이션 |
| 신규 문양 | 구별 가능한 임시 기준 경로 | 확정 마법진 디자인·정밀 허용 오차 |
| 문 개방 | 승인 완료와 화면 전환 | 실제 문·카메라 연출 |
| 사운드 | 기존 공통 효과음, 필요 시 무음 | 층별 음악·전용 효과음 |
| 서사 | 진행 이해에 필요한 최소 문구 | 조사 기록·대사·서사 연출 |

임시 문양도 실제 획수·마나 소비·시작점·경로 판정이 있어야 한다. 이름만 다른 같은 경로 15개나 자동 성공 버튼은 사용하지 않는다. 모든 새 연출은 reduced motion 설정에서도 진행이 완료되어야 한다.

## 4. 임시 무대와 UI의 연결

- 전투·진행 상태와 무대 표현을 분리한다. 적 HP나 예약 피해는 3D 노드 상태에서 읽지 않는다.
- 기존 층은 현재 RealityKit 무대를 유지하고, 새 층은 준비 완료를 정상적으로 반환하는 임시 무대를 사용한다.
- 임시 무대에서도 적 등장·피격·보상·하강 표현 요청은 안전하게 완료된다. 존재하지 않는 모델·애니메이션·카메라 경로를 기다리지 않는다.
- 나중에 새 모델과 배경이 들어오면 무대 및 표현 연결만 교체하고 동일한 전투·가방·보상 UI를 유지한다.
- 공통 UI의 클릭과 드로잉 영역이 정적 적 이미지나 임시 배경에 가려지지 않게 한다.

## 5. 브랜치와 진행 순서

아래 이름은 제안이며 아직 생성하지 않았다. develop의 확인된 기준에서 순서대로 작은 PR로 통합한다. 뒤 작업이 앞 변경을 필요로 하면 통합 후 최신 develop에서 분기한다. 동시에 같은 진행·전투 화면을 중복 수정하는 병렬 작업은 피한다.

### 01. feat/floors75-foundation

- 신규 층·장면·체크포인트와 임시 무대 준비 경로.
- 보유 주문과 장착 주문, 기본 대응 지정, 신규 튜토리얼 상태의 데이터 구조.
- 저장 버전 전환 및 기존 저장 복원 원칙 적용.
- 기존 10~8층 유지, 개발용 진입점에서 7층 임시 화면 확인.
- 완료 조건: 새 3D 파일 없이도 신규 층 UI가 정상적으로 표시되고, 기존 저장이 사라지거나 시작을 막지 않음.

### 02. feat/floors75-combat-effects

- 버프·디버프, 예약 피해, 지연·취소, 모사 기록, 카드 봉인, 기간·중첩·소모 규칙.
- 복합 효과·조건부 공격·예약 방어·전투당 사용 제한·금서 비용.
- 피해 순서, 적 처치 시 예약 정리, 다음 주기 단계 전환.
- 완료 조건: 실제 전투 엔진에서 효과가 동작하고 주요 처리 순서 테스트 통과. 임시 시각 표현과 무관하게 계산 가능.

### 03. feat/floors75-spells-rewards

- 총 20종 주문과 신규 15종 임시 문양, 신규 하강 제출 문양 6개.
- 9~5층의 실제 3종 선택 보상 및 6층 고정 습득.
- 기존 카드·상세·등급 배지를 데이터 기반으로 확장.
- 실제 시험 각인과 보상 확정·저장.
- 완료 조건: 9층 세 선택이 서로 다른 주문을 주고, 8층에서도 실제 주문을 얻음. 20종이 각각 자신의 문양과 효과로 동작.

### 04. feat/floors75-loadout-hud

- 들어가기 → 가방·준비 → 전투 시작 연결.
- 최대 6종, 봉인 해제 필수, 공격·방어 각 1종 이상 검사.
- 기본 대응 주문 지정, 전투 중 교체 금지, 재도전 준비.
- 기존 전투 UI에서 6장 배치와 디버프 분류, 예약·버프·모사·봉인 표시.
- 대상 선택이 필요한 주문의 실제 입력 흐름.
- 완료 조건: 단순 목록이 아닌 기존 게임 스타일의 실제 준비·전투 화면으로 전투를 조작할 수 있음. 터치 영역과 문양 입력 영역을 유지.

### 05. feat/floor7-playable

- 8층 엔딩에서 7층 진입으로 연결.
- 첫 6종 보유 안내, 잔류체·관리자, 보스방 봉인, 선택 보상, 2단계 하강.
- 교정 방벽과 강공격 약화, 관리자 단계 전환과 기존 봉인 해제 활용.
- 완료 조건: 기존 8층 이후부터 7층 전체를 실제 화면에서 플레이하고 6층 입구 도달.

### 06. feat/floor6-playable

- 출력 저하 고정 습득과 8종 중 6종을 고르는 가방 튜토리얼.
- 잔류체의 증폭→예약→대응 안내와 관리자 복수 예약 패턴.
- 방어막을 억지로 추가하지 않고 상태 효과 표시와 실제 계산 일치.
- 보스방 문·선택 보상·2단계 하강.
- 완료 조건: 버프 제거와 등록된 예약 취소가 구별되고, 지연·감소 효과를 화면에서 확인하며 5층 입구 도달.

### 07. feat/floor5-playable

- 잔류체의 모사 학습, 관리자의 카테고리별 모사와 카드 봉인.
- 지정된 공격·방어 및 봉인 해제 보호, 봉인 만료·정화·재사용 처리.
- 보스방 문·보상·2단계 하강·4층 문 개방 및 확장 종료.
- 완료 조건: 어떤 유효한 기본 대응 구성에서도 선택 카드 봉인으로 진행 불능이 되지 않고 확장 종료까지 도달.

### 08. feat/floors75-integration

- 9층부터 5층 종료까지 실제 이어하기·재도전·보상·가방·학습 통합 확인.
- 기존 10~8층 회귀 확인, 화면 겹침·잘림·입력 방해 수정.
- 선택 보상 조합과 2획 공격 중심 구성, 정화·디버프 미장착 구성 확인.
- 개발 전용 층별 진입·주문 구성 고정 시작점을 정리하되 일반 플레이에서 숨김.
- 완료 조건: 새 게임 전체 경로와 기존 저장 이어하기 모두 가능하며, 최종 화면 캡처 및 남은 임시 항목 목록 제공.

## 6. 저장 데이터 이행 원칙

- 저장 삭제를 요구하지 않는다. 기존 9층에서 실제 얻은 방벽 관통은 유지한다.
- 8층의 옛 보상은 실제 주문이 없었으므로 저장된 선택 후보 ID에 대한 명시적 새 주문 매핑을 작성한다. 과거 선택 정보가 없는 완료 저장은 한 번만 보상 보완 절차를 제공하는 안으로 처리한다.
- 새 장착 필드가 없으면 보유 주문으로 유효한 초기 구성을 만들고, 선택 결과를 안내한다. 아직 배우지 않은 주문을 임의로 지급하지 않는다. 위의 보상 보완만 별도 처리한다.
- 기존 데모 완료 저장은 7층 진입으로 이어갈 수 있게 변환한다. 이미 받은 보상을 다시 받는 경로는 차단한다.
- 알 수 없는 주문·장면 값이나 손상된 구성은 가능한 진행 정보를 보존하며 복구하거나 명확한 오류로 처리한다. 조용히 새 게임으로 덮어쓰지 않는다.

## 7. 확인할 테스트

### 전투·진행

- 최대 6종과 필수 카테고리 검사, 보호 주문 지정, 전투 중 구성 고정.
- 예약 생성 시점·증폭 확정·한 번만 지연·취소·적 처치 후 정리.
- 모사 기록이 성공 주문에만 반응하고 한 번만 발동.
- 카드 봉인 중 기본 대응 보장 및 원래 시점 해제.
- 금서 비용·사용 제한·실패 처리, 신규 주문별 대표 경계 조건.
- 보상 중복 방지, 6층 고정 습득 1회, 하강 2단계 성공 유지, 패배 복귀.
- 기존 버전 저장과 데모 완료 저장의 이행.

### 실제 화면

- 앱 빌드 및 사용 가능한 시뮬레이터에서 진행 경로 실행. 기기 환경에 따라 Pencil 실제 입력은 별도 실기기 확인 항목으로 명시.
- 기존에 지원하는 화면 크기·방향에서 6장 카드와 입력판이 겹치지 않음.
- 상태·예약·모사·봉인 표시가 실제 전투 상태와 일치.
- 일반 설정과 reduced motion에서 보상·문 개방이 멈추지 않음.
- 기존 9·8층과 신규 층의 서체·프레임·버튼·HUD 일관성을 화면 캡처로 비교.

## 8. 최종 전달물

1. 기존 층의 UI 규칙으로 7~5층 전체를 플레이할 수 있는 프로토타입.
2. 9~5층의 실제 보상 선택, 20종 주문, 가방 구성, 신규 규칙 튜토리얼.
3. 핵심 화면 캡처와 실행·검증 결과.
4. 임시 배경·적 이미지·문양·음향 목록과 추후 교체 위치.
5. 검증 후 남은 기획·수치 문제 목록. 모델 부재를 이유로 실제 전투 흐름을 미완료 상태로 두지 않음.
