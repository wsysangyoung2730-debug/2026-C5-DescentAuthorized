# #131 5~7층 조우·처치 대화 연결

- 브랜치: `feat/#131-expansion-encounter-dialogue`
- 분기 기준: `fix/#130-expansion-entry-seal-ui`의 `10c1778`

## 적용 내용

기존 9~8층의 `BossNarrativeView`를 공유하여 7·6·5층의 잔류체와 관리자 조우·처치 장면을 연결했다. 기존 제작 이미지 12장을 수정 없이 에셋 카탈로그에 등록했다. 잔류체는 장면당 1개, 관리자는 장면당 3개로 총 24개 대사를 사용하며, 관리자 처치의 마지막 대사는 주인공 독백이다.

스토리 공개 순서는 7층의 기준점과 주인공 생체 파형, 6층의 원인보다 먼저 기록된 승인, 5층의 분리된 기억과 반복 복원으로 이어진다.

## 진행 순서

1. 잔류체 조사 완료 및 출전 준비 → 조우 이미지·대화 → 전투
2. 잔류체 승리 → 처치 이미지·대화 → 관리자 구역 봉인문 입력
3. 관리자 출전 준비 → 조우 이미지·대화 → 전투
4. 관리자 승리 → 처치 이미지·대화 → 두루마리 보상 선택·학습 → 하강문 입력

대화에서는 기존 타자 효과, 자동 진행 켜기/끄기, 수동 탭 진행, 주인공 독백 색상을 재사용한다. 자동 진행 설정은 층 사이에서도 이어진다. 앱 비활성화와 입력 일시 정지 시 자동 진행을 멈추며, 연속 탭으로 종료 이벤트가 중복 실행되지 않도록 막는다.

새 배경 이미지는 전체가 보이도록 표시하여 관리자 오른쪽 정보 패널의 잘림을 피한다. 화면 비율이 다르면 검은 여백이 생길 수 있다. 기존 9~8층 배경의 표시 방식은 유지한다.

## 저장 및 재개

- 조우 대화 중 종료: 같은 방의 출전 준비로 돌아가 대화를 다시 재생하며 현재 HP를 유지한다.
- 전투 중 종료: 기존 방식대로 출전 준비로 돌아가 HP를 회복한다.
- 처치 대화 중 종료: 처치 대화를 처음부터 재생하고 이후 단계로 이동한다.
- 새 대화 단계는 기존 전투 HP 및 승리 회복 규칙을 변경하지 않는다.

## 최소 검증

- 진행·HP·방 연결 관련 기존 테스트 11개 통과.
- 조우 대화 중 전투 시작 거부, 대화 종료 후 전투 진입 검증 포함.
- 7→6→5층 전투·보상·하강 진행 및 기존 8→7층 연결 검증 포함.
- iOS 시뮬레이터 Debug 빌드 성공 (arm64 및 x86_64, 코드 서명 제외).
- 시뮬레이터 실행 및 화면별 수동 검증은 생략했다.

## 사용자 확인 항목

- 세 층의 잔류체·관리자 조우/처치 이미지가 각각 맞는지 확인.
- 자동 진행 속도와 수동 탭, 주인공 독백 표시 확인.
- iPad에서 대화창이 이미지의 중요한 정보를 가리지 않는지 확인.
- 처치 대화 후 봉인문, 두루마리, 하강문 순서 확인.
