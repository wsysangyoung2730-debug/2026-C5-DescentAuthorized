# #133 체크포인트 재진행과 조우·처치 이미지 정렬

브랜치: `fix/#133-checkpoint-replay-reward-history`  
기준: `fix/#132-expansion-camera-reward-restart`의 `551ef6e`

## 동작

- 기존 10~8층 체크포인트에 7~5층 절차를 연결한다.
- 7층·5층: 두루마리 조사 → 잔류체 조우 → 중간 봉인문 → 관리자 조우 → 보상 선택 → 하강 승인.
- 6층: 조사와 잔류체 조우 사이에 출력 저하 두루마리 학습 체크포인트를 둔다.
- 5층 하강 완료도 별도 체크포인트로 제공한다.
- 조사 지점으로 이동하면 해당 층과 이후 층의 조사 기록을 비운다. 조우 이후 단계로 직접 이동할 때는 그 단계의 선행 조사가 완료된 상태로 복원한다.
- 9층 입구와 8층 입구도 조사 지점임을 명시하며, 해당 지점 복귀 시 조사를 다시 진행한다.
- 같은 방의 같은 지점을 다시 선택해도 화면 식별자와 3D 장면을 새로 생성한다. 조사창, 대화 진행, 보상 선택, 문 개방 연출이 이전 상태로 남지 않도록 한다.
- 체크포인트 이동은 HP 100으로 시작하고, 하강 승인 지점의 두 단계 입력도 처음부터 진행한다.

## 보상 변경 전파

현재 보유 주문과 각 층의 최신 선택 이력을 분리한다. `selectedRewardIDs`는 복원 시점까지의 선택이고, `checkpointRewardChoices`는 층별 최신 선택이다.

예시:
1. 7층에서 1번 주문을 선택하고 6층 관리자까지 진행한다.
2. 7층 보상 선택 지점으로 복귀하면 7층 이후 보상 주문·훈련·숙련 상태가 현재 보유 목록에서 제거된다.
3. 2번 주문을 선택하면 7층의 선택 이력이 2번으로 바뀐다.
4. 이미 열린 6층 관리자 체크포인트로 바로 이동해도, 7층의 최신 2번 주문으로 보유 목록을 구성한다. 이전 1번 주문은 보유 목록과 편성에 남지 않는다.
5. 6층에서 선택한 주문은 6층 보상 이전 지점에는 지급하지 않는다. 이후 지점으로 이동할 때 그 층의 최신 선택을 반영한다.

해금 범위는 유지하되 아직 도달하지 않은 체크포인트는 열지 않는다. 이력이 없는 기존 저장의 필수 선행 보상에는 기존 복원 정책인 첫 후보를 사용한다. 이전에 실제 선택한 보상이 있으면 그 선택을 우선한다.

## 저장 호환성

- 저장 버전 6에 층별 선택 이력을 추가한다.
- 버전 5까지의 선택 목록에서 이력을 복원한다.
- 7~5층을 모두 `demoComplete`로 저장했던 기존 데이터는 실제 층과 진행 단계에 맞는 체크포인트로 변환한다.
- 기존 `demoComplete` ID는 7층 조사 지점의 저장 식별자로 유지한다.

## 조우·처치 이미지

7~5층의 조우·처치 이미지 12장은 원본 비율을 보존하고 상단 중앙으로 정렬한다. 화면 비율 차이로 남는 세로 여백을 아래에 두어 이미지에 포함된 상단 제목과 설명을 보존한다. 자동 대화와 하단 대화창 동작은 유지한다.

## 최소 검증

- 기존 진행·확장·HP 관련 테스트 27개 통과.
- 체크포인트 회귀 테스트 6개 통과: 모든 체크포인트 저장/재실행, 층별 세 보상 재선택, 조사 반복, 6층 재학습, 실제 단계별 해금, 버전 5 저장 이관.
- iOS 시뮬레이터 Debug 빌드 통과(arm64/x86_64).
