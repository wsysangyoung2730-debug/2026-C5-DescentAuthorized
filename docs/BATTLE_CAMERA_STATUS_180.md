- 브랜치: `fix/#180-battle-camera-and-status`
- 원격 갱신 후 확인한 최신 로컬 작업인 #179 (`9d5465d`)에서 분기했다. 원격 최신 #167보다 이후의 완료된 작업을 포함한다.
- 4–1층 조우·처치 이미지 24장을 먼저 제작했다. 실제 설치된 다른 층의 이미지 규격을 확인하여 모두 1448×1086 PNG로 맞췄다. 각 캐릭터 및 해당 잔류체방/관리자방의 Blender 렌더를 참조했다.
- 이미지의 앱/대화 연결은 요청대로 보류했다. 이번 브랜치는 전투 화면과 3층 방 오류 수정만 포함한다.

## 원인과 변경

### 기본 시점 버튼

카메라 복귀 함수는 회전과 확대를 정상적으로 되돌리고 있었다. 하층에서 항상 나타나는 상단 상태 표시의 가로 스크롤 영역이 기본 시점 버튼 위치와 겹쳐 터치를 가로채는 구조였다.

상태 영역이 있을 때 버튼을 그 아래로 배치하고, 버튼을 누르면 진행 중인 카메라 제스처 상태도 초기화하도록 했다. 상층과 하층 모두 기존의 공통 카메라 복귀 함수를 사용한다.

### 3층 관리자방

- Blender 원본의 난간·연결 파이프·바닥 무늬 등 365개 곡선 객체가 USD `BasisCurves`로 남아 RealityKit에서 표시되지 않았다. 원본의 두께와 위치를 유지한 메시로 변환하고 기존 재질을 연결했다.
- 원본 카메라 y=-12는 방 앞쪽 벽 밖에 있었다. 회전 시 외부가 드러나지 않도록 y=-7.5로 이동했다.
- 천장 패널 24개가 위쪽만 향해 내부에서는 뒷면이 사라졌다. 기존 재질의 안쪽 면을 추가했다.
- 기본·중간·낮음 그래픽 품질에 모두 적용했다. Blender 원본 파일은 수정하지 않았다.

### 시전 패드

선택 주문을 시전할 수 없거나 공격 연출 중일 때 입력 패드를 숨긴다. 커다란 ‘시전할 수 있는 주문이 없습니다’ 안내판도 제거하여 적의 피격 모습을 가리지 않도록 했다. 패드가 숨겨지면 해당 영역의 카메라 입력 제외도 해제한다.

### 전투 효과

효과를 받는 대상을 기준으로 화면 상단을 나눴다.

- 왼쪽 청록색 ‘내 상태’: 내 보호·강화·약화·봉인.
- 오른쪽 주황색 ‘적 상태 · 위협’: 적 강화·방벽·기록·예약 공격 및 적에게 적용한 약화.

위치뿐 아니라 제목·아이콘·테두리 색도 구분한다. 기존 위협 처리 순서 설명은 오른쪽에 유지한다.

## 검증

- 최소 회귀 테스트 29개 통과: 상태 소유자 분류, 종료 후 상태 제거, 하층 전투, 장면 경로.
- 최종 iPad 시뮬레이터 Debug 빌드 성공.
- 4층 잔류체 A 및 3층 관리자방에서 회전·확대 후 기본 카메라 복귀 진단 통과. 3층 행렬 오차 0, 4층 최대 오차 약 0.00000006, 시야각 오차 모두 0.
- 3층 좌우 회전 한계 및 천장 방향의 런타임 캡처로 난간·파이프·바닥 무늬·천장 내부 표시 확인.
- 세 품질 자산 모두 복원 메시 365개, 천장 내부 면 24개, 남은 곡선 0개, 깨진 텍스처 참조 0개 확인.
- 이미지 24개 규격·중복 해시·ZIP 무결성 확인.
- Mac이 잠겨 있어 실제 버튼 터치 자동화는 수행하지 못했다. 전체 게임 플레이와 실기기 조작 검증은 포함하지 않는다.

진단 수치는 `docs/reality-assets/camera-reset-180.json` 및 `floor3-validation-180.json`에 저장했다. 워크스페이스의 `output/validation-180/`에 시뮬레이터 캡처가 있다. 이미지와 갤러리는 `output/imagegen/floors-4-1-room-matched/`, 전체 묶음은 같은 상위 폴더의 `floors-4-1-room-matched.zip`이다.
