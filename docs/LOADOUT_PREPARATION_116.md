# 9층 출전 준비와 조우 전환 (#116)

브랜치: `feat/#116-floor9-loadout-tutorial`  
기준: `feat/#115-loadout-ui-assets`의 `790bb16` (develop은 이미 포함됨)

## 변경

- 배운 주문 종류만 봉인 보호 상태와 누락 안내에 표시한다. 9층의 첫 준비에서는 배우지 않은 방어 주문과 봉인 해제를 요구하지 않는다. 방어 주문을 배운 뒤의 필수 편성 규칙은 유지한다.
- 9층 및 8층 잔류체에 별도 준비 장면을 둔다. 입장 → 출전 준비 → 시작하기 → 조우 대사 → 전투 순서다. 준비 화면 뒤에서 대화가 먼저 실행되지 않는다.
- 돌아가기는 같은 구역의 진입 화면을 표시한다. 진입을 다시 누르면 준비 화면을 연다. 준비 취소로 조사나 학습을 반복하지 않으며, 시작 전 편집은 확정하지 않는다.
- 기존 대화/전투 저장, 체크포인트 이동, 패배 재도전은 준비 단계부터 복원한다. 기존 대화 저장의 HP는 유지한다.
- 기본 전체 화면 모달을 없애고 0.24초 페이드로 전환한다. 앱 및 시스템의 동작 줄이기 설정에서는 전환 애니메이션을 생략한다. 준비 중에는 배경 3D 장면의 터치와 접근성 탐색을 차단한다.
- 첫 9층 준비에서 검은 배경의 4단계 안내를 표시한다. 보유 주문, 편성 슬롯, 시작 버튼을 차례로 강조하며, 마지막 ‘준비하기’는 안내만 닫는다.
- 안내 중 편성 조작과 시작을 차단한다. 안내 단계/완료 상태는 기존 튜토리얼 저장 체계로 보존하며, 설정에서 다시 볼 수 있다. 출전 준비 상단에는 사용법 버튼을 두지 않는다.
- 공통 튜토리얼의 제목과 다음 버튼을 접근성 요소로 각각 노출한다.

## 검증

- Swift 전체 테스트 173개 통과. 미학습 방어 안내, 학습 후 필수 방어, 준비 단계 저장/복원, 명시적 조우 시작, 이전 대화 저장 복원, 안내 각 페이지의 저장/재개, 완료/재열람, 다른 층 제외를 검증했다.
- iPad Pro 13-inch (M5), iOS 26.5 Simulator Debug 빌드 확인.
- 시뮬레이터에서 4개 안내 페이지, 마지막 준비하기 후 편성 화면, 방어 추가 안내 미표시와 시작하기 활성 상태를 확인했다.
- 접근성 트리에서 안내 제목·본문·다음 버튼이 각각 노출되는 것을 확인했다.
- 돌아가기 → 재입장 → 시작하기 → 조우 대사의 연속 화면 검증은 UI 제어 도구의 `noWindowsAvailable (-10005)` 오류 때문에 완료하지 못했다. 진행 상태와 대화 시작 순서는 코어 테스트 및 화면 연결 검토로 확인했다.
- 물리 기기 검증은 수행하지 않았다. 기존 3D 자산은 변경하지 않았다.

## 재확인

Debug 실행 인자 `--preview-loadout-floor 9`로 첫 9층 준비를 연다. `--preview-loadout-floor 8`은 잔류체, 여기에 `--preview-boss`를 추가하면 관리자 진입 패널을 연다. 이 경로는 메모리 내 임시 저장을 사용하여 실제 사용자 저장과 업적에 영향을 주지 않는다.

1. 9층 안내에서 다음을 세 번 누르고 준비하기를 누른다. 대화 없이 편성 화면만 표시되어야 한다.
2. 돌아가기를 누른 뒤 중앙 기록실 진입을 누른다. 조사 반복 및 안내 자동 반복 없이 준비 화면으로 돌아와야 한다.
3. 설정에서 9층 출전 준비 다시 보기를 예약하고 해당 장면에 재진입한다. 안내 중 뒤쪽 주문 카드는 조작되지 않아야 한다.
4. 시작하기를 누른 시점부터 관리자 대화가 시작되어야 한다.
5. 8층 잔류체 및 관리자 준비에서도 돌아가기와 재진입을 확인한다. 배운 방어 주문을 편성에서 빼면 누락 안내가 유지되어야 한다.
